## 🎯 任务概述

**用户需求**:
> "登录账户可对坟墓信息的每一项进行单独的隐私设置，选择对外公开或者不公开或者对特定账号公开；其它账号浏览时可申请对应信息的查看权限，需要原账号授权后可访问；账号可以对隐私信息设置时效，时效过了之后可自动修改特定信息为公开访问。"

- 3 种隐私级别控制（PUBLIC, PRIVATE, SELECTIVE）

- 完整的权限申请→审批→授权→过期工作流
- 自动时效处理和访问审计

## 📊 功能详解

### 1. 隐私级别系统

**3 种隐私级别**:

```
┌─────────────┬──────────────┬─────────────────────┐
│  级别       │  符号        │  谁能看              │
├─────────────┼──────────────┼─────────────────────┤
│ PUBLIC      │  🔓 公开     │ 所有人（包括游客）   │
│ PRIVATE     │  🔒 隐私     │ 仅坟墓主人           │
│ SELECTIVE   │  🔑 选择性   │ 指定用户 + 申请用户  │
└─────────────┴──────────────┴─────────────────────┘
```

**示例配置**:
```typescript
// 字段 1：epitaph（墓志铭）
→ PUBLIC: 所有人可见

// 字段 2：selfEvaluation（自我评价）
→ PRIVATE: 仅主人可见，其他人可申请

// 字段 3：photos（照片）
→ SELECTIVE: 仅家人 [1,2,3] 可见，其他人可申请
```

### 2. 权限申请工作流

**4 个阶段**:

```
Stage 1: 申请
┌────────────────────────────────┐
│ 用户提交权限申请                │
│ - 选择字段                      │
│ - 编写申请原因                  │
│ - 系统检查是否满足要求          │
└────────────────────────────────┘
           ↓
Stage 2: 待审批
┌────────────────────────────────┐
│ 坟墓主人查看待审批列表          │
│ - 查看申请详情                  │
│ - 检查申请原因                  │
│ - 决定批准或拒绝                │
└────────────────────────────────┘
           ↓
Stage 3: 已授权
┌────────────────────────────────┐
│ 用户获得访问权限                │
│ - 在 granted_permissions 表中   │
│ - 设置有效期                    │
│ - 可以访问指定字段              │
└────────────────────────────────┘
           ↓
Stage 4: 过期
┌────────────────────────────────┐
│ 权限自动过期或被撤销            │
│ - 用户失去访问权限              │
│ - 需重新申请                    │
│ - 可再次提交申请                │
└────────────────────────────────┘
```

### 3. 时效管理机制

**关键概念**:

```
字段隐私时效:
  设置: POST /api/privacy/grave/1/field/will
  { "level": "private", "expiresAt": "2027-02-28" }
  
  效果: 2027-02-28 后自动改为 PUBLIC

权限时效:
  批准: POST /api/permissions/requests/1/approve
  { "expiresAt": "2026-03-30" }
  
  效果: 2026-03-30 后权限自动失效
```

**自动处理流程**:

```
定时任务（每小时运行）
  ↓
检查 field_privacies.expires_at < NOW()
  ↓
检查 granted_permissions.expires_at < NOW()
  ↓
调用 PrivacyService.handleExpiredPrivacy(graveId)
  ↓
自动更新: PRIVATE/SELECTIVE → PUBLIC
  ↓
删除或标记过期的权限
```

### 2. 三层验证机制

```
Layer 1: API 层
  ├─ 请求参数验证
  └─ 权限检查（需要在中间件中实现）

Layer 2: 业务逻辑层 (PrivacyService)
  ├─ 访问权限检查 (checkFieldAccess)
  ├─ 过期时间验证 (isPermissionExpired)
  ├─ 用户黑白名单检查 (isUserBlocked, shouldAutoApprove)
  └─ 自动时效处理 (handleExpiredPrivacy)

Layer 3: 数据库层
  ├─ 外键约束
  ├─ 唯一性约束
  └─ 检查约束
```

### 3. 自动过期处理 ⚠️ 关键

```typescript
// 必须在每次返回墓地数据前调用
async function getGraveDetails(req, res) {
  const graveId = req.params.id;
  
  // ⚠️ CRITICAL: 处理过期隐私
  await PrivacyService.handleExpiredPrivacy(graveId);
  
  // 现在可以安全地返回数据
  const grave = await Grave.findById(graveId);
  const filtered = await PrivacyService.filterGraveFields(grave, userId);
  
  res.json(filtered);
}
```

**效果**:
- PRIVATE 字段在 expiresAt 后自动改为 PUBLIC
- SELECTIVE 字段在 expiresAt 后自动改为 PUBLIC
- 无需手动操作
- 时间精度：秒级

### 4. 黑白名单机制

**白名单（信任用户）**:
```typescript
POST /api/privacy/grave/1
{
  "trustedUsers": [5, 6, 7],
  "requireApprovalForEachRequest": false
}

效果：
- 用户 5, 6, 7 的权限申请自动批准
- 无需坟墓主人手动审批
- 仍然受 expiresAt 限制
```

**黑名单（屏蔽用户）**:
```typescript
POST /api/privacy/grave/1
{
  "blockedUsers": [99, 100]
}

效果：
- 用户 99, 100 无法申请权限
- 无法通过白名单获得访问权
- 系统直接拒绝其请求
```

## 📞 快速问答

### Q: 为什么采用 3 种隐私级别？

**A**: 这是隐私管理的最优设计：
- 公开（PUBLIC）满足大多数用户需求
- 隐私（PRIVATE）保护敏感信息
- 选择性（SELECTIVE）平衡分享和隐私

### Q: handleExpiredPrivacy() 为什么这么重要？

**A**: 它是自动时效处理的核心：
- 在返回数据前调用，确保一致性
- 自动将过期的 PRIVATE/SELECTIVE 改为 PUBLIC
- 无需管理员手动干预

### Q: 如何保证数据安全？

**A**: 多层安全机制：
1. 类型检查（编译时）
2. 参数验证（API 时）
3. 业务逻辑检查（PrivacyService）
4. 数据库约束（存储时）

### Q: 性能会不会有问题？

**A**: 性能设计已考虑：
- 所有查询都有适当的索引
- 支持批量操作（batch approve/reject）
- 支持缓存（权限列表、隐私配置）
